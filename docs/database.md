# Database Integration Guide

This guide covers database integration in Kagaribi applications using Drizzle ORM.

## Overview

Kagaribi provides built-in database support with:
- **Drizzle ORM** integration for type-safe queries
- **Multiple database dialects**: PostgreSQL, MySQL, SQLite
- **SQLite drivers**: libsql, D1 (Cloudflare), sqlite-cloud
- **Model generation**: CLI commands for schema and model helpers
- **Database middleware**: Automatic connection initialization
- **Flexible access patterns**: Choose between shared model helpers or direct DB access

## Supported Databases

| Database | Dialect | Use Case |
|----------|---------|----------|
| PostgreSQL | `postgresql` | Production applications, complex queries |
| MySQL | `mysql` | Production applications, MySQL ecosystem |
| SQLite | `sqlite` | Development, edge deployments, serverless |

### SQLite Drivers

| Driver | Use Case | Platform |
|--------|----------|----------|
| `libsql` | Turso, local development | Node.js, serverless |
| `d1` | Cloudflare D1 | Cloudflare Workers |
| `sqlite-cloud` | SQLite Cloud | Node.js, serverless |

## Quick Start

### 1. Initialize Project with Database

```bash
# PostgreSQL
kagaribi init my-app --node --db postgresql

# MySQL
kagaribi init my-app --node --db mysql

# SQLite (libsql - default driver)
kagaribi init my-app --node --db sqlite

# SQLite with D1 (Cloudflare)
kagaribi init my-app --cloudflare --db sqlite --driver d1
```

### 2. Configure Environment

Create `.env` file:

```env
# PostgreSQL
DATABASE_URL=postgresql://user:password@localhost:5432/mydb

# MySQL
DATABASE_URL=mysql://user:password@localhost:3306/mydb

# SQLite (libsql) - local file
DATABASE_URL=file:local.db

# SQLite (libsql) - Turso
DATABASE_URL=libsql://your-database.turso.io
DATABASE_AUTH_TOKEN=your-auth-token
```

For D1, configure in `wrangler.toml`:
```toml
[[d1_databases]]
binding = "DB"
database_name = "my-database"
database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

### 3. Generate Models

```bash
# Generate a model with fields
kagaribi model new users name:string email:string age:integer
```

This creates:
- Table definition in `db/schema.ts`
- Model helper in `db/models/users.ts`
- Export in `db/models/index.ts`

### 4. Apply Migrations

```bash
# Generate migration files
npx drizzle-kit generate

# Apply to database
npx drizzle-kit push
```

### 5. Use in Your Package

```typescript
import { Hono } from 'hono';
import { createDb, createDbMiddleware } from '@kagaribi/core';
import * as schema from '../../../db/schema.js';
import * as Users from '../../../db/models/users.js';

// Create database instance (no db/index.ts needed!)
const { initDb } = createDb('postgresql', schema);

const app = new Hono()
  .use('*', createDbMiddleware({ initFn: initDb }))
  .get('/users', async (c) => {
    const users = await Users.findAll();
    return c.json(users);
  });

export default app;
```

## Database Access Patterns

Kagaribi supports two patterns for database access. Choose based on your needs.

### Pattern 1: Shared Database with Model Helpers

**Best for**: Consistent business logic across packages, shared database operations.

**Structure**:
- Model helper files in `db/models/`
- Functions like `findAll()`, `findById()`, `create()`, `remove()`
- Generated by `kagaribi model new` command

**Example**:
```typescript
// db/models/posts.ts (auto-generated)
import { getDb } from '../index.js';
import { posts } from '../schema.js';
import { eq } from 'drizzle-orm';

export async function findAll() {
  const db = getDb();
  return await db.select().from(posts);
}

export async function findById(id: number) {
  const db = getDb();
  const result = await db.select().from(posts).where(eq(posts.id, id));
  return result[0] || null;
}

export async function create(data: { title: string; content?: string | null }) {
  const db = getDb();
  const [post] = await db.insert(posts).values(data).returning();
  return post;
}

export async function remove(id: number) {
  const db = getDb();
  const [deleted] = await db.delete(posts).where(eq(posts.id, id)).returning();
  return deleted;
}
```

**Usage in package**:
```typescript
import * as Posts from '../../../db/models/posts.js';

// Simple and clean
const post = await Posts.findById(1);
const allPosts = await Posts.findAll();
const newPost = await Posts.create({ title: 'Hello', content: 'World' });
```

**Advantages**:
- ✅ Centralized business logic
- ✅ Consistent operations across packages
- ✅ Simpler package code
- ✅ Easy to add validation/formatting

**Disadvantages**:
- ❌ Requires maintaining model helper files
- ❌ Less flexible for custom queries

### Pattern 2: Per-Package Database Access

**Best for**: Package-specific queries, maximum flexibility, minimal abstraction.

**Structure**:
- No model helper files
- Direct use of `getDb()` and `schema` in packages
- Full Drizzle ORM query builder access

**Example**:
```typescript
import { Hono } from 'hono';
import { createDb, createDbMiddleware } from '@kagaribi/core';
import { eq } from 'drizzle-orm';
import * as schema from '../../../db/schema.js';

const { initDb, getDb } = createDb('postgresql', schema);

const app = new Hono()
  .use('*', createDbMiddleware({ initFn: initDb }))
  .get('/users', async (c) => {
    const db = getDb();
    const users = await db.select().from(schema.users);
    return c.json(users);
  })
  .get('/users/:id', async (c) => {
    const id = Number(c.req.param('id'));
    const db = getDb();
    const user = await db
      .select()
      .from(schema.users)
      .where(eq(schema.users.id, id));
    return c.json(user[0]);
  })
  .post('/users', async (c) => {
    const body = await c.req.json();
    const db = getDb();
    const [user] = await db
      .insert(schema.users)
      .values(body)
      .returning();
    return c.json(user, 201);
  });

export default app;
```

**Advantages**:
- ✅ Maximum flexibility
- ✅ No extra files to maintain
- ✅ Package-specific optimizations
- ✅ Direct control over queries

**Disadvantages**:
- ❌ Business logic in package code
- ❌ Potential code duplication

### When to Use Each Pattern

| Criteria | Shared Model Helpers | Per-Package Access |
|----------|---------------------|-------------------|
| Multiple packages use same table | ✅ Recommended | ❌ Avoid duplication |
| Need consistent validation | ✅ Recommended | ❌ Hard to maintain |
| Complex custom queries | ❌ Limited | ✅ Recommended |
| Simple CRUD operations | ✅ Simpler | ⚠️ More code |
| Package-specific logic | ⚠️ Needs customization | ✅ Recommended |

## Database Middleware

The `createDbMiddleware` function initializes the database connection for each request.

### URL-based Connection (PostgreSQL, MySQL, SQLite)

```typescript
import { Hono } from 'hono';
import { createDbMiddleware } from '@kagaribi/core';
import { initDb } from '../../../db/index.js';

const app = new Hono()
  .use('*', createDbMiddleware({ initFn: initDb }));
```

The middleware reads `DATABASE_URL` from:
- Node.js: `process.env.DATABASE_URL`
- Cloudflare Workers: `c.env.DATABASE_URL`

### Binding-based Connection (Cloudflare D1)

```typescript
import { Hono } from 'hono';
import { createDbMiddleware } from '@kagaribi/core';
import { initDb } from '../../../db/index.js';

interface Env {
  DB: D1Database;
}

const app = new Hono<{ Bindings: Env }>()
  .use('*', createDbMiddleware<D1Database>({
    initFn: initDb,
    envVarName: 'DB',
    isBinding: true
  }));
```

### Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `initFn` | `(source: T) => void` | Required | Database initialization function |
| `envVarName` | `string` | `'DATABASE_URL'` | Environment variable name |
| `isBinding` | `boolean` | `false` | Whether source is a binding object (D1) |

## Field Types

When generating models with `kagaribi model new`, use these field types:

### Universal Types (All Dialects)

| Type | PostgreSQL | MySQL | SQLite | Description |
|------|-----------|-------|--------|-------------|
| `string` | `text` | `varchar(255)` | `text` | Variable-length text |
| `text` | `text` | `text` | `text` | Long text content |
| `integer` | `integer` | `int` | `integer` | Whole numbers |
| `boolean` | `boolean` | `boolean` | `integer` (0/1) | True/false values |

### Auto-added Fields

Every model gets these fields automatically:
- `id`: Primary key (auto-increment)
- `createdAt`: Timestamp (defaults to current time)

### Example

```bash
kagaribi model new posts title:string content:text published:boolean views:integer
```

Generates:
```typescript
export const posts = pgTable('posts', {
  id: serial('id').primaryKey(),
  title: text('title').notNull(),
  content: text('content'),
  published: boolean('published').notNull(),
  views: integer('views').notNull(),
  createdAt: timestamp('created_at').defaultNow().notNull(),
});
```

## Scoped Databases (Monorepo Packages)

For monorepo setups where each package has its own database:

```bash
# Generate model in specific package's db directory
kagaribi model new users name:string email:string --scope packages/auth
```

This creates:
- `packages/auth/db/schema.ts`
- `packages/auth/db/models/users.ts`
- `packages/auth/db/models/index.ts`

## Database Setup

Kagaribi provides two ways to set up database connections:

### `createDb` (Recommended)

The `createDb` function automatically selects the correct Drizzle ORM driver based on the dialect. **No need for db/index.ts file**.

```typescript
// In your package
import { createDb } from '@kagaribi/core';
import * as schema from '../../../db/schema.js';

const { initDb, getDb } = createDb('postgresql', schema);
```

**API**:
- `createDb(dialect, schema, options?)`: Create database instance
  - `dialect`: `'postgresql'` | `'mysql'` | `'sqlite'`
  - `schema`: Database schema object (from `schema.ts`)
  - `options`: Optional config (`{ driver?: 'libsql' | 'd1' | 'sqlite-cloud' }` for SQLite)

**Examples for Each Dialect**:

```typescript
// PostgreSQL
const { initDb, getDb } = createDb('postgresql', schema);

// MySQL
const { initDb, getDb } = createDb('mysql', schema);

// SQLite (libsql - default)
const { initDb, getDb } = createDb('sqlite', schema);

// SQLite (D1 for Cloudflare Workers)
const { initDb, getDb } = createDb('sqlite', schema, { driver: 'd1' });

// SQLite (SQLite Cloud)
const { initDb, getDb } = createDb('sqlite', schema, { driver: 'sqlite-cloud' });
```

**Returned Functions**:
- `initDb(source)`: Initialize database with connection string or binding
- `getDb()`: Get the initialized database instance

### `createDbHelper` (Low-level API)

For advanced use cases where you need full control over the Drizzle instance creation:

```typescript
import { drizzle } from 'drizzle-orm/node-postgres';
import { createDbHelper } from '@kagaribi/core';
import * as schema from './schema.js';

const { initDb, getDb } = createDbHelper((url) => drizzle(url, { schema }));
```

**Most users should use `createDb` instead**, which is simpler and handles dialect selection automatically.

## Common Queries

### Basic Queries

```typescript
import { createDb } from '@kagaribi/core';
import * as schema from '../../../db/schema.js';
import { eq, and, or, gt, lt, desc, asc } from 'drizzle-orm';

const { getDb } = createDb('postgresql', schema);
const db = getDb();

// Select all
const all = await db.select().from(schema.users);

// Select with condition
const user = await db.select().from(schema.users).where(eq(schema.users.id, 1));

// Multiple conditions
const activeUsers = await db
  .select()
  .from(schema.users)
  .where(and(
    eq(schema.users.is_active, true),
    gt(schema.users.age, 18)
  ));

// Order and limit
const recent = await db
  .select()
  .from(schema.posts)
  .orderBy(desc(schema.posts.createdAt))
  .limit(10);
```

### Insert

```typescript
// Single insert
const [user] = await db
  .insert(schema.users)
  .values({ name: 'Alice', email: 'alice@example.com', age: 30, is_active: true })
  .returning();

// Bulk insert
const users = await db
  .insert(schema.users)
  .values([
    { name: 'Bob', email: 'bob@example.com', age: 25, is_active: true },
    { name: 'Carol', email: 'carol@example.com', age: 28, is_active: true },
  ])
  .returning();
```

### Update

```typescript
// Update single record
const [updated] = await db
  .update(schema.users)
  .set({ age: 31 })
  .where(eq(schema.users.id, 1))
  .returning();

// Update multiple records
await db
  .update(schema.users)
  .set({ is_active: false })
  .where(lt(schema.users.age, 18));
```

### Delete

```typescript
// Delete single record
const [deleted] = await db
  .delete(schema.users)
  .where(eq(schema.users.id, 1))
  .returning();

// Delete with condition
await db
  .delete(schema.posts)
  .where(lt(schema.posts.createdAt, new Date('2024-01-01')));
```

### Joins

```typescript
// Left join
const postsWithUsers = await db
  .select({
    postId: schema.posts.id,
    title: schema.posts.title,
    userName: schema.users.name,
    userEmail: schema.users.email,
  })
  .from(schema.posts)
  .leftJoin(schema.users, eq(schema.posts.userId, schema.users.id));

// Inner join
const activePosts = await db
  .select()
  .from(schema.posts)
  .innerJoin(schema.users, and(
    eq(schema.posts.userId, schema.users.id),
    eq(schema.users.is_active, true)
  ));
```

### Transactions

```typescript
await db.transaction(async (tx) => {
  const [user] = await tx
    .insert(schema.users)
    .values({ name: 'Dave', email: 'dave@example.com', age: 35, is_active: true })
    .returning();

  await tx
    .insert(schema.posts)
    .values({ title: 'First Post', content: 'Hello world', userId: user.id });
});
```

## Troubleshooting

### Database Connection Fails

**Symptom**: `Error: Database source not found: DATABASE_URL is not set`

**Solutions**:
1. Check `.env` file exists and contains `DATABASE_URL`
2. Verify database server is running
3. Test connection string with database client
4. For D1: Check `wrangler.toml` has correct binding configuration

### Migration Fails

**Symptom**: `drizzle-kit generate` or `push` fails

**Solutions**:
1. Check `db/schema.ts` for syntax errors
2. Verify `drizzle.config.ts` points to correct schema file
3. Ensure previous migrations applied successfully
4. Check database permissions

### Type Errors

**Symptom**: TypeScript errors with Drizzle queries

**Solutions**:
1. Ensure correct imports from `drizzle-orm`
2. Verify schema types match database columns
3. Run `pnpm install` to update dependencies
4. Check Drizzle ORM version compatibility

### Model Helper Not Found

**Symptom**: `Cannot find module '../../../db/models/users.js'`

**Solutions**:
1. Verify model is exported from `db/models/index.ts`
2. Check file path is correct (relative from package)
3. Run build if using TypeScript compilation
4. Ensure model was generated with `kagaribi model new`

## Best Practices

1. **Use model helpers for shared logic**: If multiple packages access the same table, use Pattern 1
2. **Use direct access for flexibility**: If you need custom queries, use Pattern 2
3. **Validate input in model helpers**: Centralize validation logic in model files
4. **Use transactions for related operations**: Ensure data consistency
5. **Index frequently queried columns**: Add indexes in schema for performance
6. **Use environment-specific databases**: Different `DATABASE_URL` for dev/staging/prod
7. **Version control migrations**: Commit `drizzle/` directory to git
8. **Test migrations before production**: Always test on staging first
